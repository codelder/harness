## Current Implementation Issues

### Issue 1: BashTool timeout not implemented (HIGH)
- API declares `timeout: u64` parameter (line 13-14 in bash.rs)
- Default is 30 seconds (line 17-19)
- But implementation uses `std::process::Command::output()` which is synchronous
- The timeout value is never used

**Fix:** Use `tokio::process::Command` with `tokio::time::timeout`

### Issue 2: GlobTool silently drops errors (MEDIUM)
- Line 57-60 in glob.rs uses `.filter_map(|entry| entry.ok())`
- This discards `GlobError` values without surfacing them
- User gets incomplete results without knowing

**Fix:** Collect into `Result<Vec<_>, _>` and propagate the first error

### Issue 3: GrepTool API/implementation mismatch (MEDIUM)
- Line 14 doc says: "File or directory path to search"
- Implementation (line 74) only reads a single file: `tokio::fs::read_to_string(&path)`
- No recursive directory search

**Fix:** Update documentation to accurately state "single file path"

### Issue 4: Unused error types (LOW)
- `ReadError::InvalidPath` (line 27-28 in read.rs) - never constructed
- `BashError::InvalidUtf8` (line 33-34 in bash.rs) - never used (code uses `from_utf8_lossy`)

**Fix:** Remove dead variants
</context>
