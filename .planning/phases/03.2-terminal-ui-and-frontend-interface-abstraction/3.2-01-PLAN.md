<task type="auto" tdd="true">
  <name>Task 1: Define the shared frontend protocol</name>
  <files>src/frontend/mod.rs, src/frontend/protocol.rs, src/lib.rs</files>
  <read_first>
    - src/lib.rs
    - src/agent/message.rs
    - src/cli/session.rs
  </read_first>
  <behavior>
    - Command/event types are presentation-agnostic
    - Events cover session lifecycle, assistant output, tool activity, status, and errors
    - No protocol type depends on ratatui, reedline, stdout, or stderr
    - Protocol module defines channel aliases or equivalent transport contract using `tokio::sync::mpsc`
    - Backpressure policy is documented for high-frequency events
  </behavior>
  <action>
Create a new `src/frontend/` module and introduce typed protocol enums/structs.

Design constraints:
- Use simple owned Rust data types (`String`, `u32`, enums)
- Keep commands minimal in v1: submit message, interrupt, exit
- Keep events sufficient for future surfaces: startup, transcript deltas, tool activity, errors, summary
- Add explicit `tokio::sync::mpsc` sender/receiver aliases or wrappers for commands and events
- Document overflow behavior: transcript and completion events must not be dropped; high-frequency status/activity events may be coalesced
- Include dedicated reminder and retry event types instead of encoding them as free-form status text
- Make the backpressure rule executable:
  - commands always use `send().await`
  - must-deliver events use `send().await`
  - best-effort events use `try_send` and may be coalesced into the latest reducer-visible value when the queue is full
- Export the protocol through `src/lib.rs`

Add unit tests that verify:
- command/event enums are constructible
- protocol types stay CLI-framework-agnostic
- the chosen must-deliver vs best-effort sending policy can be exercised in isolation with bounded channels
  </action>
  <verify>
    <automated>cargo test frontend --lib</automated>
  </verify>
  <acceptance_criteria>
    - `src/frontend/protocol.rs` defines `FrontendCommand`
    - `src/frontend/protocol.rs` defines `FrontendEvent`
    - `src/frontend/protocol.rs` defines the runtime/frontend transport contract using `tokio::sync::mpsc`
    - protocol docs identify must-deliver vs best-effort events
    - the plan explicitly commits to `send().await` for must-deliver traffic and `try_send`/coalescing for best-effort traffic
    - no `ratatui`, `reedline`, `stdout`, or `stderr` references appear in the protocol module
    - `src/lib.rs` re-exports the new modules
  </acceptance_criteria>
</task>
