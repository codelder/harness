**Why PromptHook instead of state tracking:**
- Direct detection: We know immediately when todo tool is called (from dispatch)

- No state pollution: TodoManager stays pure (only data, no event tracking)
- No race conditions: Atomic flag is set synchronously during tool dispatch
- Cleaner architecture: Hook is the rig-core idiomatic way to observe tool calls

The key insight: rig-core's PromptHook::on_tool_call() is called synchronously when a tool is invoked. We use an AtomicBool to communicate this to the Session.

Update src/agent/loop_.rs:

Add Clone derive to TodoUsageHook (required by PromptHook trait):

```rust
pub struct TodoUsageHook {
    /// Flag set to true when todo tool is called
    used_todo: Arc<AtomicBool>,
}
```

Implement PromptHook trait:
```rust
use rig::completion::CompletionModel;
use rig::agent::{PromptHook, ToolCallHookAction, HookAction};

impl<M> PromptHook<M> for TodoUsageHook
where
    M: CompletionModel,
{
    /// Called when a tool is invoked during agent execution.
    /// This is the DIRECT tool usage detection (per Python approach).
    async fn on_tool_call(
        &self,
        tool_name: &str,
        _tool_call_id: Option<String>,
        _internal_call_id: &str,
        _args: &str,
    ) -> ToolCallHookAction {
        // Direct detection: if todo tool is called, set the flag
        // This is equivalent to Python's: used_todo = True
        if tool_name == "todo" {
            self.used_todo.store(true, Ordering::SeqCst);
        }
        // Always continue with tool execution
        ToolCallHookAction::cont()
    }
}
```

**Key design:**
- The hook is called synchronously during tool dispatch
- When "todo" tool is called, we set `used_todo` to true
- Session reads this flag after agent_loop returns
- This is EXACTLY equivalent to Python's tool loop detection

**Why this is correct:**
1. Direct detection: We know immediately when todo is called
2. No state pollution: TodoManager is not involved in detection
3. No race conditions: AtomicBool is thread-safe
4. Matches Python: `if block.name == "todo": used_todo = True`

```rust
use rig::agent::PromptHook;
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::Arc;

/// Core agent loop that processes LLM responses until text output.
/// Now supports PromptHook for observing tool calls.
///
/// # Arguments
/// * `history` - Conversation history (read-only, not modified)
/// * `current_input` - The user's current input
/// * `provider` - LLM provider to use for chat completions
/// * `used_todo_flag` - Shared flag to signal when todo tool is used
///
/// # Returns
/// An `AgentTurn` containing the user input and agent response, or an error
pub async fn agent_loop<H>(
    history: &[Message],
    current_input: &str,
    provider: &crate::llm::LlmProvider,
    hook: H,
) -> Result<AgentTurn, AgentError>
where
    H: PromptHook<rig::providers::anthropic::completion::CompletionModel>
        + PromptHook<rig::providers::openai::responses_api::ResponsesCompletionModel>
        + Clone
        + Send
        + Sync
        + 'static,
{
    // Convert history to rig's Message type
    let rig_messages: Vec<rig::completion::Message> = history
        .iter()
        .filter_map(|m| match m.role {
            Role::User => Some(rig::completion::Message::user(&m.content)),
            Role::Assistant => Some(rig::completion::Message::assistant(&m.content)),
            Role::System => None, // System messages handled via preamble
        })
        .collect();

    // Call LLM with retry logic using hook-enabled chat
    let response = with_retry(MAX_RETRIES, || {
        let hook_clone = hook.clone();
        async {
            provider
                .chat_with_history_and_hook(
                    current_input.to_string(),
                    rig_messages.clone(),
                    hook_clone,
                )
                .await
                .map_err(classify_prompt_error)
        }
    })
    .await?;

    Ok(AgentTurn {
        user_input: current_input.to_string(),
        response,
    })
}
```

**Note:** This requires adding `chat_with_history_and_hook` method to LlmProvider. That's a minimal change since we're just wrapping the existing PromptRequest API.

**Alternative simpler approach:** If the generic bounds are too complex, we can:
1. Have Session create the hook and pass it to create_provider
2. Store the hook and flag in LlmProvider
3. Use them internally in chat_with_history

This keeps the API simpler while still using the hook mechanism.

```rust
use rig::agent::PromptHook;
use crate::agent::TodoUsageHook;

impl LlmProvider {
    /// Send a chat message with history and a hook for observing tool calls
    ///
    /// This method uses rig's PromptRequest API with hook support,
    /// which is required for direct tool usage detection.
    pub async fn chat_with_history_and_hook(
        &self,
        prompt: impl Into<String>,
        chat_history: Vec<rig::completion::Message>,
        hook: TodoUsageHook,
    ) -> Result<String, PromptError> {
        match self {
            LlmProvider::Anthropic(agent) => {
                // Use PromptRequest with hook instead of agent.chat()
                use rig::agent::PromptRequest;
                PromptRequest::new(agent, prompt.into())
                    .with_history(&mut chat_history.clone())
                    .with_hook(hook)
                    .await
            }
            LlmProvider::Openai(agent) => {
                use rig::agent::PromptRequest;
                PromptRequest::new(agent, prompt.into())
                    .with_history(&mut chat_history.clone())
                    .with_hook(hook)
                    .await
            }
            LlmProvider::Ollama => {
                Err(PromptError::CompletionError(
                    rig::completion::CompletionError::ResponseError(
                        "Ollama provider not yet implemented".to_string()
                    )
                ))
            }
        }
    }
}
```

```rust
use std::sync::atomic::Ordering;

// Create hook before agent_loop
let (hook, used_todo_flag) = TodoUsageHook::new();

match agent_loop(&self.messages, line, &provider, hook).await {
    Ok(turn) => {
        debug!(response_len = turn.response.len(), "Agent response received");

        // Check if todo was used (directly from dispatch via hook)
        // This is equivalent to Python's: rounds_since_todo = 0 if used_todo else rounds_since_todo + 1
        if used_todo_flag.load(Ordering::SeqCst) {
            self.rounds_since_todo = 0;
            used_todo_flag.store(false, Ordering::SeqCst); // Reset for next turn
        }

        // Build the response with optional nag reminder
        let response = if self.rounds_since_todo >= 3 {
            let has_todos = self.todo_manager.lock()
                .map(|m| !m.is_empty())
                .unwrap_or(false);
            if has_todos {
                format!(
                    "<reminder>You have pending todos. Use the 'todo' tool to update your task list.</reminder>\n\n{}",
                    turn.response
                )
            } else {
                turn.response
            }
        } else {
            turn.response
        };

        println!("{}", response);

        // Increment round counter after each agent response
        self.rounds_since_todo += 1;

        // Commit the turn to history
        self.messages.push(Message::user(&turn.user_input));
        self.messages.push(Message::assistant(&turn.response));
        self.turn_count += 1;
    }
    // ... error handling unchanged
}
```

1. Hook is created fresh each turn (flag starts false)
2. If todo tool is called, hook sets flag to true
3. After agent_loop, we check the flag
4. If flag is true, reset rounds_since_todo to 0
5. Then reset flag for next turn
6. This is EXACTLY the Python approach: direct dispatch detection
