# Phase 03.1: Code Review Fixes

## Objective

Fix issues identified in cross-AI code review of Phase 03 implementation.

## Background

Codex (GPT-5.4) reviewed the Phase 03 implementation and identified:
- 6 MEDIUM severity issues (async mutex, error handling, API consistency)
- 4 LOW severity issues (coupling, panic paths, cloning, comments)

## Scope

### MEDIUM Priority Fixes

1. **Replace std::sync::Mutex with tokio::sync::Mutex**
   - Files: `src/tools/todo.rs`, `src/cli/session.rs`
   - Rationale: std::sync::Mutex can block Tokio worker under contention

2. **Add dedicated error variant for lock failures**
   - Add `TodoError::LockPoisoned` or `TodoError::StateUnavailable`
   - Remove misleading mapping to `InvalidStatus`

3. **Fix silent lock failure suppression**
   - `session.rs:112` should log warning instead of silently returning false

4. **Make TodoItemInput.status typed**
   - Change from `String` to `TodoStatus`
   - Add serde derive to TodoStatus

5. **Unify Provider chat API**
   - Remove `chat()` method that takes `Vec<String>`
   - Keep only `chat_with_history()` with `Vec<Message>`

6. **Add ID validation**
   - Validate ID range (1-20) in TodoTool
   - Add uniqueness check in TodoManager

### LOW Priority Fixes

1. **Reduce Provider coupling** (defer to Phase 04)
   - Move tool wiring out of create_provider

2. **Remove panic paths**
   - Handle stdout flush failure explicitly
   - Precompute schema or use lazy_static

3. **Reduce unnecessary clones**
   - Build mutable history once per request

4. **Fix comment drift**
   - Update comment to match actual behavior
