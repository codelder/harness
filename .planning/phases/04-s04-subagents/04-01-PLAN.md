   ```rust
   const CHILD_SYSTEM_PROMPT: &str = r#"You are a subagent. Complete the assigned task using available tools.
   You have access to bash, read, write, edit, glob, grep, and todo tools.
   Return a clear summary of what you did and what you found."#;
   ```

   **MAX_RESULT_LENGTH constant:**
   ```rust
   const MAX_RESULT_LENGTH: usize = 10_000;
   const TRUNCATION_SUFFIX: &str = "\n... (truncated)";
   ```

   **SubagentTool struct and Tool impl:**
   - `SubagentTool` holds a `SubagentConfig`
   - `SubagentTool::new(config: SubagentConfig) -> Self` constructor
   - `impl Tool for SubagentTool`:
     - `const NAME: &'static str = "task";`
     - `type Error = SubagentError`
     - `type Args = TaskArgs`
     - `type Output = String`
     - `definition()` returns ToolDefinition with name "task", description explaining it spawns a subagent, and parameters from `schemars::schema_for!(TaskArgs)`
     - `call()` method does:
       a. Log the subagent invocation via `tracing::info!("Subagent spawned for prompt: {}...", &args.prompt[..args.prompt.len().min(80)])`
       b. Create a fresh `Arc<Mutex<TodoManager>>` via `Arc::new(Mutex::new(TodoManager::new()))` -- this is CRITICAL per research Pitfall #2, child must NOT share parent's TodoManager
       c. Call `create_provider()` with self.config fields and the fresh child todo_manager. Map error to `SubagentError::ProviderError`
       d. Call `agent_loop(&[], &args.prompt, &provider, TodoUsageHook::default())` -- empty history `&[]` is the key context isolation (CROSS-03)
       e. On Ok(turn): truncate `turn.response` to MAX_RESULT_LENGTH chars with TRUNCATION_SUFFIX if too long. Log child token usage via `tracing::info!` if turn.usage is Some. Return `Ok(truncated_response)`
       f. On Err(e): log via `tracing::warn!("Subagent failed: {}", e)`. Return `Ok(format!("Subagent error: {}", e))` -- this is the error isolation pattern (CROSS-02): always returns Ok() so the parent LLM can see the error and decide what to do, never propagates Err()
